End-to-end life of one video frame from edge capture to mobile notification Stages 1–2 on Edge (:8001) · Stages 3–5 on Server (:8000)
Stage 1: Capture & Encode
VideoSource reads frame, resizes to 960 px width, encodes JPEG at quality 90 (~96.2 KB).
ProcessEdge Node (:8001)
Stage 2: Ingest & Queue
POST /frames validates headers & magic bytes; pushes to 8-slot drop-oldest queue.
ProcessFastAPI Ingest (:8000)
Stage 3: Detect & Track
Letterbox 640×640, run NMS-free YOLO26n ONNX, match IoU + centroid tracks.
Vision StageONNX Runtime + Tracker
Stage 4: Rules & Triage
Evaluate Home/Public rules & S5 escalation; async LangGraph LLM triage on text metadata.
Decision StageRuleEngine + LangGraph
Stage 5: Store & Deliver
Write SQLite WAL record; sign HMAC-SHA256 webhook to Hermes (:8644) → Telegram.
Output StageSQLite + Hermes + UI
Privacy & Safety Invariant: Raw video frames never leave the local host; if the cloud LLM times out, Stage 4 fails open so the alert is still delivered.
